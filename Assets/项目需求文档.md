# 聚餐网站 · 项目需求文档

> 这份文档汇总目前为止聊定的所有项目决策，作为带去 Claude Code 实际开发时的参照。配合《Sullivan_人设文档.md》一起使用。

---

## 项目定位

一个给朋友们在聚餐时使用的网站，核心目的是让聚餐**更便捷、更有可玩性**。面向对象是较多数量的朋友（非单纯几个熟人小范围），需要考虑多人同时访问的场景。

**酒吧品牌名：Calypso's**（出现在酒保围裙上，后续应作为网站标题/品牌标识使用）

视觉风格：温暖爵士酒吧氛围 + 像素风格（参考《Dave the Diver》画风），核心角色是酒保 Sullivan（详见人设文档）。

---

## 四大功能模块

### 1. 点菜
- 从现有菜谱库中浏览点菜
- 支持按**食材**筛选（选一个食材，联想到含这个食材的菜）
- 支持按**口味标签**筛选（如酸甜、酸辣、清淡等）
- 支持按**情绪标签**筛选（如治愈系、想吃刺激的等）
- 支持**对话模式**：与 Sullivan 聊天，他理解用户描述的感觉/心情，推荐匹配的菜；也可以跳过对话直接进入筛选浏览
- 两种进入方式（对话 / 直接点选）最终落在同一套标签体系上

### 2. 食材联想
- 选择一个原材料（如牛肉），联想显示菜谱库中含此食材的所有菜

### 3. Potluck 看板
- 可约定时间
- 朋友可以填写自己会带的食物，避免撞菜
- 报名情况对所有参与朋友可见

### 4. 酒单
- 从现有酒单中选择
- 支持打一段文字描述"vibe"，由语言模型理解后匹配对应酒款
- 支持选择基酒后关联匹配的酒单

## 数据结构备忘

- **菜谱**：菜名 + 食材标签（多个）+ 口味标签（多个）+ 情绪标签（多个）
- **食材 ↔ 菜谱**：多对多关系
- **Potluck 报名**：谁 + 带什么 + 关联哪一次活动
- **酒单**：酒名 + 基酒 + vibe/情绪标签（多个）
- **用户偏好**（用于"记住朋友选过什么"功能）：谁 + 口味偏好 + 历史点单记录，跨多次来访持续累积

---

## 身份与权限

- 朋友第一次访问时输入名字/选择一个简单标识，网站借此识别"这是同一个人"，不需要复杂的账号密码系统
- 需要一个**只有主人（你）能访问的管理入口**，用于查看/清空数据

---

## 通知逻辑

- **不是**每次朋友修改点单/potluck 认领就发通知
- 朋友可以自由勾选、反复修改，网站上会保存实时状态
- 只有当朋友点击**"确认提交"**按钮后，才会触发一封邮件通知到主人邮箱
- 通知方式：邮件（技术上最简单可靠的起点方案）
- 未来可考虑的扩展方向（暂不做）：网页推送通知、主人看板页面用于日常查看全貌

---

## 技术方案概要

- **前端**：网页应用（不需要用户懂代码语法，由 Claude Code 生成）
- **数据库**：Supabase（托管数据库，有可视化后台，可直接在网页界面里增删改数据，不需要写代码）
- **托管/发布**：Vercel（免费额度可用，把网站发布到真实网址）
- **代码版本管理**：GitHub（同时对未来 portfolio 展示有帮助）
- **语言模型调用**：用于酒保对话理解、口味/情绪标签提取、酒单 vibe 匹配，通过 API 调用实现
- **图像素材**：AI 图像生成工具单独产出 Sullivan 及场景像素画素材，与代码开发并行推进

## 视觉与页面结构

### 全站视觉外壳
- 整体采用电影胶片画幅感：页面上下有黑色边框，边框内用绳子挂着拍立得风格的照片作装饰
- 主视觉是"坐在吧台前、正对 Sullivan"的第一人称视角

### 首页（吧台场景）
- Sullivan 位于画面中间偏右，上半身完整露出，比例适中（不宜过大显得拥挤，也不宜过小失去存在感）
- Sullivan 身后墙上有挂钩，挂着不同厨具（锅、烤架等），作为不同点菜方式的入口
- 吧台上摆放酒杯（shot / 鸡尾酒 / 啤酒等），作为进入酒单模块的入口
- 点击 Sullivan 可进入对话模式（聊天推荐菜品）
- 点击某个厨具挂钩，跳转进入该厨具对应的独立点菜子页面
- **场景切换（简化版）**：点击底部"酒吧模式"图标，Sullivan 询问"要不要切换到酒吧模式"，用户确认后播放拉绳子动画，场景切换为夜晚酒单模式；在酒吧模式下点击"菜单"图标，Sullivan 做出"把绳子拉回去"的动作，切换回白天点菜模式。**不再需要点击单个酒杯触发对话**，桌面上的酒杯/蜡烛为纯装饰，烘焙进吧台前沿素材图中，不再是独立可交互图层

### 点菜子页面（以"锅"为例，统一模板）
- 背景延续吧台场景的整体氛围（暖色调、木质质感、光影），不是脱离主视觉的纯色/空白背景
- 左侧：该厨具的视觉呈现（例如一口锅）
- 右侧：搜索框 + 食材标签选择区
- 选择食材后，匹配的菜品结果会浮现在左侧容器内（例如选"牛肉"，锅里浮现"番茄牛肉汤"等标签）
- 其他厨具（烤架等）默认沿用同一套"左侧容器 + 右侧食材搜索"模板，只替换左侧的容器视觉，保持开发效率；后续如有精力可为个别厨具做差异化呈现

### Potluck 页面
- 完全独立于吧台场景，是单独的一个页面/路由，不共享吧台视觉外壳

### 底部图标交互（新增）
画框左下角固定排列三个小图标（星露谷风格：小巧、色块简洁，色调延续暖色爵士酒吧配色），点击后触发不同效果，不全部跳转页面：

- **对话图标**：点击后在画面内弹出一个像素笔记本样式的小对话框，**只占整体画面的四分之一**（不跳转页面，是画框内的浮层）
- **菜单图标**：点击后播放"翻开书本"的彩蛋效果（合上封面 → 打开内页，中间翻页动作用代码做过渡，不需要逐帧动画素材），打开后展示菜单内容：
  - 右侧有大分类：肉菜 / 素菜
  - 点进"肉菜"后展开更细的分类标签：牛肉、羊肉、猪肉、鸡肉、鱼肉、海鲜
  - 这些分类**用文字标签实现**（手写风格字体，延续记账本视觉语言），不需要为每个分类单独生成图标素材
- **酒吧模式图标**：点击后触发场景切换逻辑（对应之前定义的拉绳/昼夜切换流程）

需要生成的素材：三个小图标（对话/菜单/酒吧模式）+ 一张笔记本道具图 + 菜单的封面图与内页图（各一张即可，翻页过程由代码实现），存放于 `assets/ui/`

### 对话气泡样式
- 采用像素游戏风格的直角对话框，带尖角指向 Sullivan
- **触发规则**：只要 Sullivan 有台词/说话，无论处于哪个场景或流程中，都播放说话嘴型动画（5帧，按 1→2→3→4→5→4→3→2→1 循环），气泡消失即停止 —— 这是通用规则，不绑定特定入口

### 待机动画细节
- **基础待机图**：命名为 `normal`，直接存放在 `assets/characters/` 目录下（不放在子文件夹中），作为角色默认展示状态，**不带任何自动动画效果**（呼吸缩放效果已取消，保持完全静止）
- **擦杯子动画**：简化为**两帧**，每帧停留 **2 秒**后切换到下一帧，两帧循环播放；随机触发规则不变——待机状态下每隔 8-20 秒之间的随机间隔触发一次，播完回到 `normal` 静态图；若用户正处于点单/对话等其他动画状态，则跳过本次触发，避免动作冲突
- **绳子待机**：不在被拉状态时，绳子图层持续做极轻微的左右摆动，模拟自然悬挂晃动

### 素材一致性要求（重要）
- 所有角色素材生成时，**不得包含吧台桌面、任何家具或场景道具**——角色的手可以悬空停留在画面中，如同搭在一个不可见的表面上，下方区域必须是干净的纯色背景
- 原因：吧台桌面由背景图层单独提供，若角色素材自带桌面痕迹，不同帧切换时会因桌面形状/角度不一致而产生"闪烁"问题
- 已生成但带有多余背景道具的素材，需要重新抠图清理，严重的需要用更强约束重新生成

### 素材图层与锚点
- 角色（Sullivan）与背景（场景图）分层处理，不同状态共用同一套角色素材，只切换背景层
- 绳子（rope）作为独立道具图层，与角色分开管理
- **吧台前沿素材**（`bar_counter_front.png`）：独立图层，用于制造角色"站在吧台后面"的遮挡效果。**图层堆叠顺序（从下到上）必须是**：吧台后方场景（墙、挂钩、酒柜）→ 角色 Sullivan → 吧台前沿素材，确保角色下半身被吧台前沿遮挡
- 所有角色动画素材需对齐同一锚点（如脚底/腰部位置），确保切换时不跳动、不偏移
- **尺寸校正要求**：由于 AI 图像生成时取景范围存在细微差异，不同帧素材的角色大小/位置可能不完全一致。以 `normal.png`（基础待机图）为标准锚点，其余动画帧素材需在代码渲染层做独立的缩放（scale）与偏移（offset）校正，确保头顶/肩线/脚底位置在所有帧之间保持对齐，避免切换时出现跳动
- **绳子对齐要求**：绳子道具的末端位置需要根据 `rope_pull` 系列动画中角色手部的实际抓握坐标动态对齐，而不是写死固定坐标，确保绳子始终精确落在手心位置

### 对话输入方式
- 点击底部对话图标后，下方弹出一个记事本样式的输入区（画面四分之一大小），玩家在上面打字输入回复
- 视觉延续"记账本点单"那套纸张质感 + 手写风格字体，作为同一套叙事化界面语言的延伸
- Sullivan 开口询问"想吃什么"一类的句子，同步播放 order_mode 系列动画

### 新手引导弹窗
- 首次进入首页场景时，展示热点说明气泡，教用户各个可点击区域对应什么功能：
  - 点击酒保 Sullivan → 进入聊天模式，由她推荐菜品
  - 点击吧台上的菜单 → 直接浏览完整菜谱
  - 点击墙上的厨具挂钩 → 按烹饪方式筛选菜品
  - 点击吧台上的酒杯 → 告诉 Sullivan 想喝酒 → 跳转进入酒单场景

### 昼夜场景切换（点单场景 ↔ 酒单场景）
- 触发方式：画面上方垂下一根绳子，Sullivan 拉动绳子后，灯光瞬间切换，场景从"点单模式"变为"酒单模式"（更昏黄、更暗的夜晚酒吧氛围）
- **不使用黑屏过渡**，要求视觉上是即时切换
- 场景变化：原本挂着厨具的墙面区域，切换后变为一个带灯光的酒类展示柜
- **人物形象在切换前后保持完全一致**
- **技术实现建议**：背景与角色分层处理——角色 Sullivan 作为独立图层，白天/夜晚场景共用同一套角色立绘，不需要重新生成；只有背景层（光照氛围、厨具区/酒柜区）需要准备两套美术素材，切换时替换背景层 + 做一个快速的光照滤镜过渡即可实现"瞬间切换、无黑屏"的效果，同时更省美术制作成本

## 网站语言设定

- **界面文案**：全部使用英文（按钮、导航、提示文字等）
- **Sullivan 对话台词**：使用英文
- **菜单（菜品名称）**：**中英双语**，中文原名 + 英文翻译并列显示，保留菜品本身的文化身份，不做纯翻译替代
- 其他模块（potluck、酒单）文案默认跟随英文界面语言，除非另有说明
